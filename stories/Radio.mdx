## Vue recipe

```vue
<fieldset>
  <legend>Deployment region</legend>

  <label>
    <Radio v-model="form.region" name="region" value="lagos" required />
    Lagos
  </label>

  <label>
    <Radio v-model="form.region" name="region" value="frankfurt" required />
    Frankfurt
  </label>
</fieldset>
```

`Radio` renders the real form control. A shared `name` creates the group;
`fieldset`, `legend`, labels, descriptions, and errors stay in application
markup. Label activation, arrow keys, required validation, form data, and reset
therefore remain browser behavior.

## Why there is no RadioGroup

HTML already has a radio-group contract. Adding another state container would
duplicate native mutual exclusion and create two possible sources of truth.
Klean keeps the API at the input boundary and lets the framework bind one scalar
value.

## API

- Vue uses one scalar `v-model` across radios sharing a `name`.
- React uses native `checked`, `defaultChecked`, `value`, and `onChange`.
- Svelte uses `bind:group`, `value`, and a shared native `name`.
- Every framework accepts native input attributes and caller `class` or `className`.
- There is no group, item, indicator, orientation, variant, tone, or size API.

## Styling choices

The default control intentionally keeps the browser's radio rendering and uses
`accent-current` for caller-owned colour. `Radio` renders only the native input,
so classes passed to it style the control without styling its label:

```vue
<div class="flex items-center gap-3">
  <Radio
    id="region-lagos"
    v-model="region"
    name="region"
    value="lagos"
    class="size-5 text-emerald-700"
  />
  <label for="region-lagos" class="text-sm text-gray-600">Lagos</label>
</div>
```

Keep the `id` and `for` association so the text remains the accessible name and
click target. Put `sr-only` on `Radio` only when a whole label becomes the
visual card or chip, then style that label with Tailwind's `has-[:checked]`
selector. Selected-label styling is optional caller markup, never component
behaviour.

## Durable state

The primitive does not write to local storage or the URL. Persist a saved
preference on the server. Put a shareable filter choice in the query string.
Keep a one-form selection in framework state. In every case, bind that source of
truth to the same native radio group.
