Slide confirms an action. It is therefore a real `<button type="button">`, not a
range input with slider semantics. Pointer users may drag and release beyond the
conventional 85% threshold; Enter, Space, and assistive activation use the native
button path.

```sh
npx klean-ui@latest add slide
```

## Styling progress

The root keeps ordinary `class`/`className` and exposes `data-progress` as
`start`, `middle`, `ready`, or `complete`. The internal fill and thumb expose
`data-slot="slide-fill"` and `data-slot="slide-thumb"`. Use Tailwind arbitrary
selectors when a product needs its own progress colors:

```vue
<Slide
  class="
    [&_[data-slot=slide-fill]]:bg-amber-500/10
    [&[data-progress=middle]_[data-slot=slide-thumb]]:bg-amber-500
    [&[data-progress=ready]_[data-slot=slide-thumb]]:bg-emerald-500
    [&[data-progress=ready]_[data-slot=slide-fill]]:bg-emerald-500/10
  "
  @confirm="deploy"
>
  Slide to production
</Slide>
```

There are no variants, color props, part-class props, or theme provider. The
component supplies neutral defaults; the application owns product language and
Tailwind.

## Durable behavior

- Pointer Events and pointer capture cover mouse, touch, and pen without global
  listeners.
- Releasing early, Escape, pointer cancellation, or lost capture resets without
  confirming.
- `pending` is caller-owned truth: it disables duplicate confirmation, sets
  `aria-busy`, and resets when the caller returns it to `false`.
- Measured track/thumb geometry responds to resizing and logical direction, so
  RTL works without separate markup.
- Focus stays on the button, progress stays ephemeral, and reduced-motion
  preferences remove movement transitions.

## API

Use native button attributes for naming and description. Klean adds only
`pending` and the framework-native `confirm` callback/event; `disabled` remains
the native disabled state.
