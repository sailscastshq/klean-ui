Popover is deliberately only the floating surface. A real button invokes it with
the browser's native `popovertarget` relationship. Both components keep their
ordinary `class` attribute; Klean adds no trigger component or part-specific class
prop.

```sh
npx klean-ui@latest add popover
```

The same native relationship works in React and Svelte: put `popovertarget="filters"`
on a real button and `id="filters"` on Popover. Framework syntax changes; the HTML
contract does not.

## What Popover owns

- native top-layer display and light dismissal where the platform supports it;
- collision-aware placement through a small geometry dependency;
- an older-browser fallback for invocation, outside pointer, and Escape;
- `aria-expanded`, `aria-controls`, focus return, and listener cleanup;
- optional framework-native observed state.

Composed controls such as Date Picker may open Popover programmatically with
the active source element. Popover then uses that source for placement and
focus return, matching the native `showPopover({ source })` relationship.

Popover is non-modal. It does not trap focus, lock scrolling, render a backdrop,
or assign `menu`/`dialog` roles. Menu will add composite keyboard behavior; Dialog
will use modal semantics. Open state is ephemeral and is never written to storage or
the URL.

## API

The only Klean props are behavioral geometry and optional state observation. Use
ordinary native attributes and Tailwind classes for everything else.
