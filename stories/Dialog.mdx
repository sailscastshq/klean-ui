## Native contract

Opening with `showModal()` puts the dialog in the top layer and lets the browser
own inert background content, focus containment, initial focus, Escape, and focus
return. Klean adds `closedby` policy with a backdrop fallback for older browsers,
observed state when the application needs it, safe scroll restoration, and caller-
winning Tailwind defaults.

Every dialog needs an accessible name. Point `aria-labelledby` at a visible heading
or provide `aria-label`. Use `aria-describedby` only for a short, simple description.
For long structured content, let assistive technology read the content structure
instead. Put `autofocus` on the best initial target; destructive confirmations should
normally focus Cancel.

## API

The behavioral surface is `id`, optional controlled `open`, `defaultOpen`, and
`dismissible`. Vue uses `v-model:open`, React uses `open` plus `onOpenChange`, and
Svelte uses `bind:open`. Observing state is optional: native `command`/`commandfor`
works without framework state.

The framework ref exposes the native dialog capability. Vue and Svelte expose
`showModal()`, `close(returnValue)`, and `requestClose(returnValue)`; React forwards
the actual `HTMLDialogElement`. Prefer native `<form method="dialog">` or command
buttons for ordinary completion.

There is no `DialogTrigger`, portal, provider, `ConfirmDialog`, visual variant,
focus-trap dependency, or Klean theme API. Confirmation is a semantic recipe composed
inside Dialog, not another universal component.
